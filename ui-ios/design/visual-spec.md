# CampusNet 校园网自动认证 · 视觉设计规范 v1.0

> 角色：视觉设计架构师 · 交付对象：体验设计 / 前端实现
> 目标风格：iOS 26 / iPadOS 原生感（分组留白、圆角卡片、毛玻璃层、克制色彩）
> 实现约束：单文件 HTML/CSS/JS，零外部依赖，仅系统字体 + 内联 SVG，无图片/图标字体/CSS 框架

---

## 0. 设计原则（5 条，冲突时按序号优先）

1. **一张卡只讲一件事。** 主页状态卡是全页唯一「有脸」的元素：最大圆角、最大阴影、唯一毛玻璃；其余卡片一律实心、无阴影或极浅阴影。
2. **颜色只做语义，不做装饰。** 中性面板永远是中性色；彩色只允许出现在「环 / 状态点 / 状态文案 / 主按钮 / 进度条」这五处，单屏彩色面积 ≤ 8%。
3. **玻璃只给浮层。** 毛玻璃仅用于：侧栏、Tab Bar、主页状态卡、Toast。普通卡片不用玻璃——层级靠**高度（阴影 + 留白）**表达，不靠透明度堆叠。
4. **数字必须等宽。** 在线时长、IP、服务器地址、倒计时、重连次数全部 `font-variant-numeric: tabular-nums`，倒计时与时长用 mono 字族，避免每秒跳动。
5. **双主题同构。** 浅/深两套只是同一批变量取不同值，不改结构、不改圆角、不改字号；深色不是反相，而是「降亮度 + 提边缘对比」。
6. **同一信息只编码一次**（v1.2 新增）。环 = 进行中（indeterminate），副行 = 当前阶段（语言），glow = 接近程度（连续量）；一旦某信息已有编码，**禁止**再加第二套 UI（分段点、百分比、双进度条）。两个进度语义同屏 = 用户两个都不信。

**明确避免**：紫蓝渐变铺底、彩色大色块背景、alpha>0.2 的大面积阴影、纯黑 #000 正文、玻璃套玻璃、emoji 当图标、填充/线性图标混用、圆角种类超过 6 种、hover 位移超过 1px、状态色用作按钮底色（除绿/琥珀的 tint 变体外）。

## 3. 尺寸系统

### 3.1 间距阶梯（4pt 基准，只用这些值）
`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`

| 场景 | 值 |
|---|---|
| 卡片内边距（桌面 / 移动） | 24 / 20 |
| 卡片间距（垂直） | 16（移动 12） |
| 卡片内元素间距 | 标题→内容 12，内容→操作 20，行间 8 |
| 内容区外边距 | 32 / 24（桌面 / 平板），16（移动） |
| 玻璃浮层内边距 | 16 |
| 列表行高 | 52（单行）/ 56（带副标题） |
| 数据格高 | 64 |
| 按钮高 | 主 50（桌面 44）/ 次 40 / 小 32 |
| 触控最小热区 | 44×44（移动硬性） |

### 3.2 圆角阶梯（6 档，不得新增）
| 变量 | 值 | 用途 |
|---|---|---|
| `--r-xs` | 6px | 徽标、状态 pill、进度条端 |
| `--r-sm` | 10px | 输入框、行内编辑器、分段控件 |
| `--r-md` | 12px | 侧栏项、次级按钮、日志嵌块 |
| `--r-lg` | 16px | 标准卡片、Toast |
| `--r-xl` | 20px | **主页状态卡**、侧栏玻璃面板 |
| `--r-pill` | 999px | 主按钮、开关、Tab 指示 |

嵌套规则：内层圆角 = 外层圆角 − 内边距（20 − 8 = 12），避免「圆角套圆角」视觉错位。

### 3.3 阴影配方（卡片「高度」只有 3 级）

```
/* L1 标准卡片 —— 几乎不可见，只做分离 */

dark : 0 1px 0 rgba(255,255,255,0.03) inset, 0 10px 24px -14px rgba(0,0,0,0.70)

/* L2 玻璃浮层（侧栏、Tab Bar） */
light: 0 1px 0 rgba(255,255,255,0.72) inset, 0 12px 32px -16px rgba(16,16,20,0.14)
dark : 0 1px 0 rgba(255,255,255,0.10) inset, 0 12px 32px -16px rgba(0,0,0,0.80)

/* L3 主状态卡 —— 全站唯一最强阴影 */
light: 0 2px 6px rgba(16,16,20,0.05), 0 24px 48px -18px rgba(16,16,20,0.16)
dark : 0 1px 0 rgba(255,255,255,0.08) inset, 0 24px 56px -20px rgba(0,0,0,0.90)

/* 状态光晕（仅状态卡环，0.18 alpha 上限） */
已连接 0 0 44px rgba(52,199,89,0.18)
连接中 0 0 48px rgba(10,108,255,0.22)   /* 深色 0.26 */
失败   0 0 40px rgba(255,59,48,0.16)
暂停   0 0 32px rgba(255,149,0,0.12)
未连接 none
```

### 3.4 hairline 处理
- 一律 `border: 1px solid`，**不用** `transform: scaleY(0.5)` 的伪元素方案（玻璃层上会发灰）。
- 卡片内分隔线：`border-top: 1px solid var(--c-sep)`，左右内缩 20px（`margin-inline: 20px`）——iOS 分组列表特征。
- 玻璃层描边必须叠加顶部高光：`box-shadow: inset 0 1px 0 var(--c-glass-highlight)`，否则边缘在深色下发脏。
- 不用 `outline`，焦点环用 `box-shadow: 0 0 0 3px var(--a-soft)`。

## 4. 毛玻璃配方

```css
/* 桌面侧栏 / Tab Bar（大面） */
background: var(--c-sidebar);
backdrop-filter: blur(28px) saturate(190%);
border: 1px solid var(--c-glass-border);
box-shadow: 0 1px 0 var(--c-glass-highlight) inset, <L2>;

/* 主页状态卡（中大面，需见内容流动） */
background: var(--c-glass);
backdrop-filter: blur(20px) saturate(170%);
border: 1px solid var(--c-glass-border);
box-shadow: 0 1px 0 var(--c-glass-highlight) inset, <L3>;

/* Toast（小面，位于内容之上） */
background: var(--c-glass);
backdrop-filter: blur(16px) saturate(160%);   /* 小面积降低 blur，避免糊字 */
/* 例外：Sheet 场景（Toast 位于 scrim 之上，z50 > z30）→ 撤掉 backdrop-filter，
   改用不透明底（浅 #FFFFFF / 深 #1C1C22）+ --c-glass-border + L3 阴影，见 §9.4 */
```

| 参数 | 浅色 | 深色 | 原因 |
|---|---|---|---|
| 底 alpha | 0.62–0.72 | 0.58–0.66 | 深色下 alpha 更高会显「灰塑料」，需保留背景暗部 |
| blur | 20–28px | 20–28px | 一致；仅 Toast 降到 16px |
| saturate | 170–190% | 150–170% | 深色过度饱和会出现彩边 |
| 顶部高光 | `rgba(255,255,255,0.72)` | `rgba(255,255,255,0.10)` | 深色高光是唯一「厚度」线索 |
| 外描边 | `rgba(16,16,20,0.06)` | `rgba(255,255,255,0.10)` | 深色描边必须更亮 |

**降级**：`@supports not (backdrop-filter: blur(1px))` → 玻璃层改为不透明底（浅 `rgba(255,255,255,0.94)`，深 `rgba(26,26,32,0.94)`），描边与高光保留。
**禁止**：玻璃层内再嵌玻璃层；玻璃层上的文字一律 ≥13px 且至少 `--t-2`（玻璃底不可控，`--t-3` 在玻璃上只剩 ~4.1:1）。

## 5. 布局架构

### 5.1 断点

| 断点 | 宽度 | 结构 | 导航 |
|---|---|---|---|
| Compact | `< 768px` | 单列，卡片全宽，边距 16 | iOS 底部 Tab Bar |
| Medium | `768–1023px` | 单列，内容居中 `max-width: 720px` | 侧栏收窄为 **88px 图标栏**（图标 22 + 下方 10px 文字） |
| Regular | `≥ 1024px` | 侧栏 + 内容区 | 侧栏 **264px** 完整（图标 + 文字） |
| Wide | `≥ 1400px` | 主页内容区转 2 列 | 侧栏 264px |

窗口 `min-width: 360px`，`min-height: 560px`。

### 5.2 桌面（Regular / Wide）

- 侧栏：宽 264px，固定；内边距 `20px 12px`；顶部品牌块（图标 28 + 「CampusNet」Headline + 版本号 Caption `--t-3`）高 64；导航项高 44、圆角 12、图标 20、间距 2px；选中态 `background: var(--a-soft)`、文字/图标 `--a-text`、字重 600；hover 态 `--c-fill`；底部固定「v1.0.0 · MIT」Caption `--t-3`（v1.1 由 `--t-4` 上调）。
- 内容区：`padding: 24px 32px 40px`；内部 `max-width: 760px`，左侧对齐（不做居中，避免与侧栏产生双重留白）。
- Wide（≥1400px）主页：`grid-template-columns: minmax(0,1fr) 340px; gap: 24px`。左列 = 状态卡 + 数据块 + 自动重连开关；右列 = 最近运行日志（`position: sticky; top: 24px`）。
- 内容区顶栏（toolbar）：高 52px，左侧 inline 标题 17/600，右侧 1–2 个图标按钮 32×32 圆角 10；滚动时标题降至 15/600 + 出现 1px `--c-sep` 底边。

### 5.3 移动（Compact）

- Tab Bar：高 49px + `env(safe-area-inset-bottom)`；玻璃；3 项（主页 / 我的 / 设置）；图标 26px（线性 24 viewBox 放大）、标签 Caption 2 **11px**；激活 `--a-text`，未激活 `--t-bar`（图标与标签同色）；无顶部描边，仅 `inset 0 1px 0` 高光 + 上边 1px `--c-sep` 分隔（替代阴影）。
- 内容区：`padding: 0 16px calc(49px + env(safe-area-inset-bottom) + 16px)`；顶部 Large Title 34/700，滚动 32px 后折叠为 17/600 居中标题 + 玻璃顶栏（高 44 + safe-area-top）。
- 状态卡：`border-radius: 20px`，内边距 20，`min-height: 268px`；按钮**全宽**、高 50。

#### 6.3.1 正在连接 · 三段副行（消费 `probe:start` / `probe:ip`，不新增状态；v1.2 移除段指示器）

副行是**单行替换**，不做跑马灯：容器固定 `min-height: 18px`、`line-height: 18px`、`overflow: hidden`、`text-overflow: ellipsis`、13px mono `--t-2`；文案切换只允许 `opacity` 交叉淡入（`--ease-state`），禁止纵向滚动/打字机，避免高度抖动。

| 阶段 | 触发 | 副行文案（定稿，v1.2） | glow 乘数 → 实际值（基 `rgba(10,108,255,.22)`） |
|---|---|---|---|
| S1 | `CONNECTING` t=0 同帧（**不等事件**） | `正在检测网络` | ×0.6 → `0 0 48px rgba(10,108,255,.13)` |
| S2 | `probe:ip` | `已获取地址 10.10.1.101` | ×0.8 → `0 0 48px rgba(10,108,255,.18)` |
| S3 | 提交认证（`auth:*` 未回） | `正在提交认证` | ×1.0 → `0 0 48px rgba(10,108,255,.22)` |

**阶段感只由「副行语言 + glow 强度」两件东西表达，删除 3 段微指示器**（v1.1 曾提出）。理由（采纳 ux）：① 环已是 indeterminate，再加 determinate 分段会诱导用户读格数，而 3 格各只亮一次 → 时间预期反而更差；② 与副行同一信息双重编码；③ 逐段点亮会让同屏动画变成 3 个，违反 §8「同屏 ≤2」。glow 递增必须在 **80ms 内一次性跳到下一档**（仅 `box-shadow` 过渡，非循环、非逐段动画），不得做成 0.13↔0.22 的循环呼吸（那样会被读成"又在重连"）。

**CONNECTING 最短驻留 600ms（team-lead 裁决，视觉执行细则）**：
- 600ms 内即使认证回执已到，也**不离开 CONNECTING**：环继续匀速旋转，副行停在 S3 `正在提交认证`（不回退、不清空）。
- 600ms 内的「取消」**必须保持可用**（它是这 600ms 里用户唯一的出口），禁止置灰/禁用样式。
- 600ms 到点且结果已到 → **一次性**切入目标状态：环形态 + 环色 + 标题 + 按钮同时过渡（`--ease-state`），副行直接替换为目标状态副行；**禁止在 600ms 边界先静止一下再切**——那一下会被读成「卡住了」，正好抵消 600ms 驻留想建立的稳定感。
- 切入 CONNECTED 时环从**当前旋转相位**补到满弧 360°，不得重置相位再从 12 点重画（会看到环「弹一下」）；切入 FAILED 同理，从当前相位收到 40% 弧。
- 副行不得先清空再换（避免中间闪过一帧空行）：新文案直接以 opacity 交叉替换。

副行长度上限（v1.2 收紧）：**桌面 ≤28 全角 / 移动 ≤18 全角**（移动卡内容宽 = min 360 − 32 margin − 40 padding = 288px；13px 中文按 1em=13px 计约 22 字为物理上限，留 4 字余量给数字与标点；mono 栈下 CJK 若回落为 2ch 会更宽，18 是跨字体安全的保守值）。超长必须**改文案**，不允许靠 ellipsis 兜底——被截断的副行比没有副行更糟。

#### 6.3.3 认证被暂停 · 三因分支（同一状态，三种视觉）

**状态点形状是「暂停」的辨识特征，三种原因一律保留方点 r2，只换色相**（形状词汇表见 §6.3.5）——若锁号/欠费把点变圆，就会和 FAILED 的红圆+叉混淆。

| 原因 | 环 | 状态点 | 环色 / 点色 | 标题 | 主按钮（**只用 2 字或 4 字**） |
|---|---|---|---|---|---|
| `retry_exhausted`（重试 5 次耗尽） | 虚线环 + 40% 弧，无 glow | **8px 方点 r2** | `--s-warn` | 「自动重连已暂停」 | 「恢复重连」（4 字）降权主要：h 44、`rgba(255,149,0,0.14)` 底、`--s-warn-ink` 600、r-pill |
| `account_locked`（Portal 锁号，致命） | 虚线环 + 40% 弧，无 glow | **8px 方点 r2** | `--s-danger` | 「账号已被锁定」 | 「重新检测」（4 字）**次要**：h 40、`--c-fill` 底、`--t-1` 600、r12；**不提供「重试」** |
| `account_arrears`（欠费，致命） | 虚线环 + 40% 弧，无 glow | **8px 方点 r2** | `--s-danger` | 「账号已欠费」 | 「重新检测」（4 字）**次要**：同上 |

规则：① 致命类主按钮**禁止** `--a-fill` / `--s-danger` 填充——它不代表「再试一次」，红色只说明「线路断了」，不能用来催点击；② 三种原因的按钮统一 4 字（`恢复重连` / `重新检测`），共用 `min-width: 96px`，状态切换时零横向位移；③ 副行交由 ux 定稿（`ux-motion-spec.md` §6.1），视觉只约束长度 ≤18 全角。

#### 6.3.4 倒计时（视觉职责，逻辑由体验/前端定）

- 文案：`{剩余秒数} 秒后自动重试`，数字用 mono + `tabular-nums`、600 字重、`--s-warn-ink`；单位与「秒后自动重试」用 Footnote 400 同色。
- 进度条：**2px 高、`--r-pill`、`--s-warn`、宽度 = 剩余/本次总时长；必须 `linear`**（与环旋转同属「连续 / 真实时间」类，见 §8，这是全站与曲线族并列的 linear 例外）。总时长按尝试次数传参（12/20/30/45s），**不得在前端写死 12**，否则第 4 次重试的条会提前走完。
- 位置：卡片内底部，左内缩 = 右内缩 = 20（移动）或 24（桌面），条与 Footnote 间距 8，Footnote 与按钮间距 20；条出现时卡片高度锁定，不因条出现/消失改变 `min-height`。
- 取消/暂停/成功时：条与文案同时消失（`--ease-exit`），不留空位（卡片高度用 `min-height` 兜底，不重新回流）。

#### 6.3.5 状态点形状词汇表 + `kind` → 视觉矩阵（v1.2）

**形状 = 状态类别，颜色 = 严重程度。** 形状永不被颜色替代，颜色永不被形状替代；同屏只有 1 个状态点。

| 形状 | 规格 | 独占语义 |
|---|---|---|
| 实心圆 + 12% 外圈 | 8px + 6px | 已连接（唯一带外圈的状态） |
| 空心圆（2px 描边） | 8px 空心 | 未连接 / 离线 |
| 实心圆 + 交叉小叉 | 8px + 10px 叉（1.5 stroke） | 认证失败 |
| 方块 r2 | 8px 方 | 认证被暂停（**三种原因共用，只换色**） |
| 圆 + 呼吸（1↔0.4） | 8px | 正在连接（唯一带呼吸动画的状态） |

| `kind` / 状态 | 环形态 | 环色 | 状态点（形状 + 色） | 主按钮视觉（底 + 权重 + 高） |
|---|---|---|---|---|
| `IDLE` | 12% 灰空轨，无缺口 | `--s-idle` | 空心圆 `--s-idle` | `--a-fill` 实底 / 主要 / 44–50 |
| `CONNECTING` | 270° 弧 linear 旋转 | `--s-busy` | 实心圆 `--s-busy` + 呼吸 | `--c-fill` 底 + `--t-2` 字 / 次要 / 40（hover 字转 `--s-danger-ink`） |
| `CONNECTED` | 100% 满弧 | `--s-ok` + glow .18 | 实心圆 + 外圈 `--s-ok` | `--c-fill` 底 + `--a-text` 字 / 次要 / 40 |
| `FAILED` · `credential` | 40% 弧，端点圆 | `--s-danger` | 实心圆 + 叉 `--s-danger` | `--a-fill` 实底 / 主要 / 44–50 |
| `FAILED` · `portal_service` | 同上 | `--s-danger` | 实心圆 + 叉 `--s-danger` | 同上 |
| `FAILED` · `network` | 同上 | `--s-danger`（环与点仍标红：确实是故障） | 实心圆 + 叉 `--s-danger` | 同上 |
| `PAUSED` · `retry_exhausted` | 虚线环 + 40% 弧 | `--s-warn` | **方点** `--s-warn` | `rgba(255,149,0,.14)` 底 + `--s-warn-ink` 字 / 降权主要 / 44 |

注意 `FAILED · network` 的一个刻意不对称：**副行墨色不标红（`--t-2`），但环与点标红**。理由——环/点是「机器视角的事实」（线路断了，确实异常，用户需要一眼看到异常）；副行是「对用户的说法」（不是你的错），不该用红色指责用户。文案由 ux 定稿，视觉只管这两层的颜色分工。

按 team-lead 裁决落地：`network` 的**标题**为「网络不可达」，墨色 `--t-1`，与该状态其他文案一样**永不带色**（全站状态卡标题一律 `--t-1`，这是硬规则，不是特例）。红色只允许出现在**环与状态点**这两个非文本元素上——即「文字不指责用户，图形如实报警」。若后续要求 `network` 整卡零红色，注意两个不可行的改法：环降灰会被读成「未连接」；改警告黄会与 `PAUSED` 撞语义。可行方案只有「环+点同时降 `--s-idle` 灰 + 副行保持中性」，但这会让「网线松了」看起来像「你没连」，不建议——如需采用请先与我确认再改。

## 7. 图标规格（全部内联 SVG）

## 8. 动效视觉语言（时长由体验设计定）

- **曲线族命名**（统一 `cubic-bezier`，不使用 `ease`/`ease-in-out` 这些默认值）：
  - `--ease-enter` = `cubic-bezier(0.16, 1, 0.30, 1)` — 入场族（卡片出现、Toast 下滑、页面切换）
  - `--ease-exit` = `cubic-bezier(0.70, 0, 0.84, 0)` — 退出族（Toast 上滑消失、卡片收起）
  - `--ease-state` = `cubic-bezier(0.32, 0.72, 0, 1)` — 状态切换族（状态卡颜色/环形态/按钮文案，所有「同尺寸替换」）
  - `--ease-press` = `cubic-bezier(0.40, 0, 0.20, 1)` — 按压族（scale 0.97 → 1，仅此一族允许 scale）
  - **`linear` 例外族（v1.2 明确）**：任何**连续 / 无限循环 / 真实时间**的运动一律 `linear`——① 连接中环旋转（`animation-iteration-count: infinite` 下非匀速会在每圈闭合点顿挫，首尾速度不接）；② 按钮内 spinner；③ 倒计时进度条。这三者的「匀速」本身就是语义：匀速 = 还在跑，没有在加速也没有在减速；给它们加缓动会被误读为「快好了」或「卡住了」。
- **视觉原则**：
  1. 只动 `opacity / transform / background-color / box-shadow`，禁止动 `width/height/top/left`（避免布局重排导致的抖动）。
  2. 同屏动画数量 ≤ 2；状态切换时环与文案同时过渡，但按钮**先**更换文案（防误触）。
  3. 连续动画（连接中环旋转、光标闪烁）必须 `transform` 驱动且可被 `prefers-reduced-motion: reduce` 完全关闭（关闭后仅保留静态缺口环 + 文案）。
  4. 位移距离族：`4px`（微）/ `12px`（Toast、卡片入场）/ `24px`（页面切换）；不出现 >32px 的位移。
  5. 缓动「重量感」从轻到重：Toast < 按钮 < 卡片 < 状态环（环最重，因为它代表真实网络过程）。

## 9. 与体验/性能对齐的视觉条款（v1.1 增补）

### 9.1 按压与状态切换的三层时序（v1.2 采纳 ux 裁决）

| 层 | 内容 | 触发点 | 时延要求 |
|---|---|---|---|
| **L1 按压** | scale 0.97 + `--a-fill-press` | `pointerdown` | **≤16ms，不等 IPC** |
| **L2 状态卡** | 标题「正在连接…」/ 环起转 / 按钮换「取消」/ 副行 S1 `正在检测网络` | **t=0 同帧**（点击即切，不等任何事件） | 同帧 |
| **L3 副行真实进展** | S2 `已获取地址 …`、S3 `正在提交认证` | `probe:start` / `probe:ip` / 回执 | 收到即换，交叉淡入 |

采用 t=0 切 L2 的依据（ux 的可取消性论证，权重高于我 v1.1 的「防闪状态」）：IPC 空档里按钮若还是「连接」，用户**没有出口**只能重复点击，而这个操作的失败代价是「账号被连试 5 次锁号」；且 t=0 副行 `正在检测网络` 在 200ms 窗口内为真，不构成欺骗。

**异常路径（保留我 v1.1 的约束）**：220ms 内仍未收到 `probe:start` → 按钮**保持「取消」，不再二次改文案**（改文案会造成第二次位移），仅加 `aria-busy`；5s 无任何事件 → Toast 报错（不透明底，见 §9.4）并把副行落到 `网络不可达 · 网络失败 1/5`。

**最短驻留与 cancel**：CONNECTING 至少停留 600ms 才允许落到 CONNECTED / FAILED；这 600ms 内「取消」保持可用（唯一的出口，禁止禁用样式）；到点若结果已到则一次性切态，环从当前旋转相位补/收，不重置相位（§6.3.1）。

**按钮文字宽度锁定**：容器 `min-width: 96px` + `text-align: center`；`连接`/`取消` 均 2 字，`重新连接`/`恢复重连`/`重新检测` 均 4 字——**按钮文案只允许 2 字或 4 字两档**，同一容器内不跨档（跨档必横向跳动）。

### 9.2 骨架屏（仅在 >200ms 时启用）
- **状态卡永不骨架化**：它必须用缓存配置立刻渲染出 IDLE 形态（环 → 空灰轨，副行 → `正在读取配置…`），保证首屏有一个完整视觉锚点。
- 仅「数据块」与「日志」骨架化：块底 `--c-fill`、`--r-xs` 6px；数据格 label `60×12`、value `96×16`、间距 8；日志行 `100%×12`，行距 6。
- 骨架**默认静态不闪**（避免首屏就动）；只有等待 >600ms 才启用 1.6s `linear` 扫光（`rgba(255,255,255,0.35)` 12% 宽，深色 `rgba(255,255,255,0.06)`）。
- 骨架 → 真实内容切换只用 `opacity`（`--ease-enter`），几何必须完全对齐（同高度、同间距），**不允许高度跳变**。

### 9.3 日志区域几何（与 200 行 / 18px 行高对齐）
- 行高锁死 `18px`（12/18 mono `tabular-nums`），行内不加 padding，靠 `line-height` 撑开。
- 卡内可视：**桌面 5 行 = 90px**（`max-height: 90px; overflow-y: auto`），6 行起出现细滚动条（`6px` 宽、`--c-fill-strong`、无箭头）；**移动 3 行 = 54px，禁止卡内滚动**（触屏上嵌套滚动是陷阱，只给最近 3 条 + 「查看完整日志」入口）；DOM 保留 200 行，超出丢弃头部（滚动位置在底部时丢头不产生跳动）。
- 时间戳列宽固定 `56px`（`HH:MM:SS`），右对齐、`--t-3` 12px；正文 `--t-1` 12px；两者间 8px，**不用竖线分隔**（1px 竖线在 12px 行里会显脏）。
- 完整日志页：虚拟列表行高 18px、容器 `padding: 8px 0`，行 hover 整行 `--c-fill`、选中行 `--a-soft`，行内不做圆角（整行高亮，避免长列表出现锯齿状色块）。

### 9.4 层级与玻璃冻结（z-index 标尺，v1.2 补坑）

`背景 0` → `内容 1` → `侧栏/Tab Bar 10` → `吸顶 toolbar 20` → `下拉/Sheet 遮罩 scrim 30` → `Sheet 40` → `Toast 50` → `模态确认 60`。

遮罩色：浅 `rgba(16,16,20,0.28)`、深 `rgba(0,0,0,0.52)`；Sheet 容器 `--r-xl 20`（顶部两角圆、底部两角直角）、宽 `min(560px, 100%)`。

**玻璃冻结（必修）**：scrim（z30）压在侧栏 / Tab Bar（z10）之上时，玻璃的 backdrop 采样被上层半透明层破坏，会**突变**成实心色块（不是渐变）。两处必须处理：
1. **`scrim` 打开的同时**，给侧栏与 Tab Bar 加 `.glass-frozen`：撤掉 `backdrop-filter`、直接切到 §4 的不透明降级配方，并与 scrim 同步过渡（时长用 ux 的 `--d-md`）。视觉理由比机制更硬：遮罩下的玻璃必须**停止采样**，否则侧栏透出的内容 + 遮罩后的内容 = 两个前景，层级暗示自相矛盾。
2. **z > 30 的浮层一律不用 `backdrop-filter`**：Toast 在 scrim 之上时，采样源是半透明黑，blur 结果接近纯色，不如直接用不透明底——更干净且少一次合成。Toast 底：浅 `#FFFFFF`、深 `#1C1C22`，描边 `--c-glass-border`，阴影用 L3。
3. Toast 触发于 Sheet 内的动作时，**水平居中于 Sheet 而非窗口**（否则看起来浮在遮罩外面，用户会以为 Sheet 已经关了）。

#### v1.2.1 勘误：副行上限的判据改为两类（team-lead 裁决，架构师已收工，由 ux 代录）

**问题**：单一「≤18 全角」是**纯中文的代理指标**，用来判含 ASCII 地址/时间的混合串会**系统性误杀合规文案**。

反例——`已连接` 状态副行：

| 串 | 全角折算 | 实测宽度 | 真实结论 |
|---|---|---|---|
| `IP 10.10.1.101 · 会话 02:14:36` | ≈26 全角（**超 18**） | ≈**228px**（15 ASCII×7.8 + 2 CJK×13 + 9 ASCII×7.8） | 288px 内余 60px，**完全合规** |
| `已获取地址 10.10.1.101` | 13 全角 | ≈159px | 合规 |

若按单一 18 全角执行，这条最常用的成功态副行会被判违规，前端只有两个选择：改掉一条本来正确的文案，或者忽略规则。**规则一旦误判就会被实现侧整体忽略**，那等于废掉——这是本条勘误的全部理由。

**定稿判据（两类，取代单一全角计数）**

| 类型 | 判据 | 上限 | 适用 |
|---|---|---|---|
| 纯中文文案 | 全角字数 | 移动 ≤18 / 桌面 ≤28 | `正在检测网络`、`网络已断开，正在重连`、`请联系网络中心缴费` |
| 含 ASCII 地址/时间/数字的混合串 | **实测渲染宽度** | ≤288px（移动） | `IP 10.10.1.101 · 会话 02:14:36`、`已获取地址 10.10.1.101` |

**动态拼接超限时的降级优先级**（顺序不可换）：① 先丢 IP（数据块与「我的」页已常驻同一值）→ ② 再丢后缀动作提示 → ③ 绝不出现 `已获取地址 10.10.1.10…` 这类截断。
