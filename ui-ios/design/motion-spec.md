## 0. 令牌扩展（唯一新增，其余全部引用视觉规范）

### 0.1 时长阶梯（6 档 + 3 个具名特殊值，不得新增）

| 令牌 | 值 | 语义 | 典型用途 |
|---|---|---|---|
| `--d-xxs` | 80ms | 即时反馈 | 按压底色变化、秒位数字替换 |
| `--d-xs` | 120ms | 微动 | 退出淡出、按钮文案替换、行高亮消退 |
| `--d-sm` | 160ms | 小位移 | chevron 位移、分段控件指示块、Toast 队列切换 |
| `--d-md` | 220ms | 标准 | Toast 进出、日志插入、开关 thumb、分组入场 |
| `--d-lg` | 320ms | 状态切换 | 状态卡环形态/色彩/文案、数字滚动、Sheet 回弹基线 |
| `--d-xl` | 420ms | 大场面 | 引导页步骤切换、页面首次入场总时长上限 |
| `--d-sheet` | 340ms | Sheet 进入 | 底部 Sheet 上滑（具名，一次性） |
| `--d-dwell` | 2600 / 4000ms | Toast 停留 | 成功·信息 / 错误（含动作时 5000ms） |
| `--d-count` | 12000ms | 倒计时条单周期 | 失败自动重试第 1 次 |

### 0.2 曲线族（引用视觉规范 §8）

| 令牌 | cubic-bezier | 用途 |
|---|---|---|
| `--ease-enter` | `cubic-bezier(0.16, 1, 0.30, 1)` | 入场：卡片、Toast、页面、Sheet |
| `--ease-exit` | `cubic-bezier(0.70, 0, 0.84, 0)` | 退出：淡出、收起 |
| `--ease-state` | `cubic-bezier(0.32, 0.72, 0, 1)` | 同尺寸替换：状态卡、开关、数字、回弹 |
| `--ease-press` | `cubic-bezier(0.40, 0, 0.20, 1)` | 按压族（**唯一允许 scale 的曲线**） |
| `--ease-loop` | `linear` | **例外族**：仅用于「连续 / 无限循环 / 真实时间」的三类运动——① 连接中环旋转 ② 按钮内 spinner ③ 倒计时进度条 |

> **例外说明（v1.2 升级为族）**：视觉规范 §8 要求「不使用 linear」。但**匀速本身就是语义**——匀速 = 还在跑，没加速也没减速。给这三类运动加缓动会被读成「快好了」或「卡住了」：
> - 环旋转与 spinner：`animation-iteration-count: infinite` 下非匀速曲线首尾速度不接，**每圈闭合点必然顿挫**；
> - 倒计时条：非匀速会向用户传达错误的剩余时间比例（前快后慢会被读成"时间不多了"）。
>
> 因此 `linear` 只允许出现在上述三处，且必须可被 reduced-motion 关闭（倒计时条改为阶梯跳格表达比例）。

### 0.3 位移与缩放族（硬上限）

| 类别 | 允许值 | 说明 |
|---|---|---|
| 位移 | `4px` / `12px` / `24px` | 不出现 >32px 位移；Sheet 用 `translateY(%)` 而非 px |
| 缩放 | `0.97`（按压） | 除按压外**禁止** scale；光晕呼吸只动 opacity |
| stagger | `40ms` | 最多 5 项，第 6 项起与第 5 项同帧 |

### 0.4 交互原则 6（v1.2 新增，与视觉规范 §0 并列）

> **同一信息只编码一次。**

主页状态卡在同一时刻只允许一条信息拥有一种编码：

| 信息 | 唯一编码 | 禁止的第二套 |
|---|---|---|
| 正在进行中 | 环的旋转 | 额外进度条 / 步骤器 / 骨架 |
| 处在哪个阶段 | 副行文案（自然语言） | 三段指示器 / 阶段圆点 |
| 接近完成的程度 | glow 透明度三档 | 百分比数字 / 环形进度弧 |
| 剩余等待时间 | 倒计时条 + `{n} 秒` 文案 | 第二处倒计时 / Toast 重复播报 |

这条原则直接来自 v1.1 的「3 段指示器」之争：两个进度语义并列时，用户会去读更弱的那一个（2px 色块），而它读不出真实进度，结果比没有更差。

### 1.2.1 裁决：「点击即进 CONNECTING」vs「等 `probe:start` 再变」

视觉 v1.1 提出「按下去有反馈、状态等 `probe:start` 再变，避免网络层没判定时 UI 先骗人」。**体验侧裁决：状态卡在 t=0 立即进 `CONNECTING`，按压反馈独立于 IPC**。二者不矛盾，是两层：

| 层 | 责任 | 时延 | 是否等 IPC |
|---|---|---|---|
| L1 按钮按压 | `pointerdown` → scale 0.97 + `--a-fill-press` | **≤16ms**（一个合成帧） | 否 |
| L2 状态卡 | 标题/环/按钮切 `CONNECTING` | t=0 同帧 | 否 |
| L3 副行真实进展 | `正在检测网络` → `已获取地址` → `正在提交认证` | 各段由事件驱动 | **是**（`probe:start` / `probe:ip` / 提交回执） |

**为什么不等 `probe:start`（3 条，按权重排序）**

1. **可取消性**：若 t=0 不把按钮换成「取消」，在 IPC 空档（典型 20–80ms，异常可达数百 ms）里用户**没有出口**，只能重复点击。Nielsen #3「用户控制与自由」要求任何长时间操作可中止。我的 cooldown 600ms 只拦重复提交，不提供逃生口。
2. **感知连续性**：点击 → 释放回弹 220ms → 环起转 320ms 若能接在一条动效里，用户读作「一次连续动作」。等事件再变，常见表现是「按压已归位、界面静了 200ms、然后环突然开始转」，这正是要消灭的两段感。
3. **不算欺骗**：t=0 时的副行是 `正在检测网络`——我们确实即将/正在发起探测，这句话在 200ms 窗口内为真；若 IPC 5s 无响应→ `网络不可达` + `网络失败 1/5`，结果诚实。真正的欺骗是「显示正在连接但根本没发请求」并在超时后假装成功，那是状态机 bug，不是乐观切换的错。

**接受视觉的哪一半**：`pointerdown` 反馈确实**不能**等 IPC（≤16ms 硬指标），且 **pending 期不改按钮文案**这条只适用于「超过 220ms 仍未进入 CONNECTING」的反常情况——此时按钮保持「取消」+ spinner，**不再二次改字**（避免二次位移）。正常路径下按钮在 t=0 就已是「取消」，不会出现二次位移（`连接`/`取消` 同为 2 字，`重新连接`/`取消` 靠 `min-width 96px` 锁定）。

### 1.2.2 `CONNECTING` 最短驻留 600ms（team-lead 裁决，v1.2.1 收录）

| 项 | 规则 |
|---|---|
| 最短驻留 | 进入 `CONNECTING` 后 **≥600ms** 才允许离开——**但只约束自动转移（T2 成功 / T3 失败）**。用户点「取消」（T4）**立即生效**，不受 600ms 限制：用户意图优先于动效节奏，让"取消"等 200ms 才响应会被读成按钮失灵 |
| 为什么 | 局域网 Portal 常在 80–300ms 内返回。若不设下限，状态卡会「切过去闪一下又切回来」，用户读不出发生过什么，且 320ms 的状态动效被打断两次（视觉上像卡顿） |
| 等待期间的表现 | 环**保持 Continuous 旋转、相位不重置**；副行停在当前阶段文案不动；「取消」保持可用（400ms 后可点，见 §1.7） |
| 到点行为 | **一次性切态**：若结果早已返回，600ms 到点那一帧直接切到 `CONNECTED` / `FAILED`，**不做** `CONNECTING → FAILED → CONNECTING` 的连切 |
| 超时计时起点 | 各阶段超时（3s / 5s / 15s）**从进入 CONNECTING 起算**，与最短驻留互不干扰（600ms ≪ 3s，无冲突） |
| 状态卡形态 | **无 pending 变体**——全程只有 `CONNECTING` 一种形态；按压态是按钮级的（`scale .97` + `--a-fill-press`），不改卡片 |
| 与动效的关系 | 600ms 只是「最早离开时刻」，不改变 §3.5 的 320ms 替换动效时长；若 600ms 到点时有新转移已排队，动画从当前插值接管 |

### 1.3 禁止转移（前端需显式拦截）

| 禁止 | 原因 | 拦截表现 |
|---|---|---|
| `IDLE → PAUSED` | 暂停语义仅由连续失败产生 | 无入口，不可能构造 |
| `PAUSED → CONNECTED` | 必须先经一次真实认证 | 只能经 `CONNECTING` |
| `CONNECTED → PAUSED` | 在线状态不累计失败 | 心跳失败只走 T10/T11 |
| `FAILED → FAILED`（重复进入） | 会造成倒计时叠加、双条 | 同状态再触发只重置计时器，**不重播动效** |
| `CONNECTING → PAUSED`（由取消触发） | 取消是用户意图，不是失败 | 走 T4 到 `IDLE` |
| 倒计时进行中再次启动倒计时 | 双 timer 竞态 | 启动前必须 `clearTimeout`，单例 timer id |

### 1.4 `CONNECTING` 的三段副行文案（同一状态内的阶段推进，不新增状态）

| 阶段 | 触发 | 副行（13/18 mono，`--t-2`） | 字数 | 环 | 超时 |
|---|---|---|---|---|---|
| S1 探测 | 进入 CONNECTING 立即 | `正在检测网络` | 6 | 270° 旋转 | 3s |
| S2 取址 | 获得本机 IP | `已获取地址 10.10.1.101` | 13 | 270° 旋转 | 5s |
| S3 提交 | 开始 POST /eportal/ | `正在提交认证` | 6 | 270° 旋转 | 15s |

阶段推进动效：副行 `opacity` 1→0（`--d-xs` / `--ease-exit`）→ 新文案 0→1（`--d-xs` / `--ease-enter`，延迟 60ms），环**不重播**（保持连续旋转，避免"重新开始"错觉）。容器锁 `min-height / line-height: 18px` + `white-space: nowrap` + `overflow: hidden`（**不用 `text-overflow: ellipsis`**，见下方超限规则），**禁止打字机与纵向滚动**（每秒抖动会让下方按钮位移）。

**长度判据（v1.2.1 定稿，两类取代单一全角计数）**

| 类型 | 判据 | 上限 | 例 |
|---|---|---|---|
| 纯中文文案 | 全角字数 | 移动 **≤18** / 桌面 **≤28** | `正在检测网络`(6)、`网络已断开，正在重连`(11)、`请联系网络中心缴费`(9) |
| 含 ASCII 地址/时间/数字的混合串 | **实测渲染宽度** | 移动 **≤288px**（≈36 ASCII）/ 桌面 ≤760px | `IP 10.10.1.101 · 会话 02:14:36`（≈228px）、`已获取地址 10.10.1.101`（≈159px） |

为什么必须分两类：单一「18 全角」是**纯中文的代理指标**，用来判混合串会系统性误杀。`IP 10.10.1.101 · 会话 02:14:36` 全角折算 ≈26 字（判违规），实测仅 **228px**，288px 里余 60px（实际完全合规）。若按单一 18 全角执行，这条最常用的成功态副行会被迫改掉，或逼前端忽略整条规则——**规则一旦误判就会被整体忽略，等于废掉**。

**移动端 288px 的核算**：内容宽 360 − 32（margin）− 40（card padding）= 288px。13px CJK 按 1em 计物理天花板 22 字；但 mono 栈下 CJK 常回落 2ch（≈15.6px/字），22 字就不够用，取 18 对两种字体度量都安全。

**超限处理必须改文案，禁止 `ellipsis` 兜底**——被截断的失败原因等于没写，且截断位置通常正好吃掉最关键的动作提示。

**动态拼接降级规则**（IP / 学校名可能超长）：静态部分必须达标；若拼接后超限，**按优先级丢动态部分**——① 先丢 IP（数据块与「我的」页已常驻同一值）→ ② 再丢后缀动作提示 → ③ 绝不出现 `已获取地址 10.10.1.10…` 这类截断。

**与视觉规范的同步**：`visual-spec.md` §9.7 已以 v1.2.1 勘误收录同一判据；该文其余出现「≤18 全角」的位置（§2 排印规则、§6.3.1、§9.6-4）一律以本条为准。

定稿三段：`正在检测网络`(6) / `已获取地址 10.10.1.101`(159px) / `正在提交认证`(6) 全部通过。

### 1.4.1 关于「3 段微指示器」——不建议加（体验侧结论）

视觉 v1.1 为 CONNECTING 增加了「3 段 16×2px 指示器」。**体验侧建议移除**，三条理由与一条降级条件：

| # | 问题 |
|---|---|
| 1 | **同一张卡两个进度语义**：环的旋转已表达「进行中（indeterminate）」，三段表达「第几阶段（determinate）」。用户会试图去读「现在走到第几段」，而它只有 3 格、每格只亮一次，读不出实际进度 → 产生比没有更差的时间预期。违反原则 1「一张卡只讲一件事」。 |
| 2 | **与副行冗余编码**：副行已用自然语言说清所处阶段（`正在检测网络` / `已获取地址` / `正在提交认证`）。同一信息用两种编码并列，注意力被分散到更弱的那个（2px 色块）。 |
| 3 | **动画并发超限**：阶段推进时若逐段点亮，则同屏出现「环旋转（连续）+ 副行 cross-fade + 指示器点亮」= 3 个并发动画，违反视觉规范 §8.2「同屏 ≤2」。 |

**若视觉坚持保留**，必须同时满足以下 3 条才可上线：① 瞬时切换，`--d-xxs` 仅 opacity，**禁止逐段点亮动画**；② 全程 `aria-hidden="true"`（不新增播报源）；③ 移动端隐藏（328px 宽度下它与副行争夺视觉轴，且 `min-height` 兜底会额外占 10px）。

**结论（v1.2）：视觉已删除该指示器，替代方案落成数值。**

阶段感交给「副行文案 + glow 强度」，三档一次到位：

| 阶段 | glow（`--s-busy` 基色 α=.22） | 视觉值 | 过渡 |
|---|---|---|---|
| S1 检测网络 | ×0.6 | `rgba(10,108,255,0.13)` | 进入 CONNECTING 即为该档 |
| S2 已获取地址 | ×0.8 | `rgba(10,108,255,0.18)` | **80ms 内一次性跳到该档**（只过渡 `box-shadow`） |
| S3 提交认证 | ×1.0 | `rgba(10,108,255,0.22)` | 同上 |

**硬禁止：不得把这三档做成 0.13 ↔ 0.22 的循环呼吸。** 循环呼吸 = 「还在重连」的既有语义（`CONNECTED` 用呼吸表示"活着"、失败重连也用它），一旦拿来表达阶段，会与真正的重连撞车，用户会把"阶段推进"读成"又断了一次"。

用户读到的是「越来越接近」，但不被要求数格子——符合 §0.4 原则 6。

### 1.5 `PAUSED` 与 `FAILED` 的原因分流

| 错误类别 `kind` | 判定 | 落到 | retryCount | netFailCount | 倒计时 | 状态卡标题 | 副行 |
|---|---|---|---|---|---|---|---|
| `credential` 账号或密码错误 | Portal 返回密码错码 | `FAILED` | ✅ | ❌ | ✅ | `认证失败` | `账号或密码不正确 · 第 3/5 次重试` |
| `portal_service` Portal 服务异常 | 5xx / 解析失败 / 页面改版 | `FAILED` | ✅ | ❌ | ✅ | `认证失败` | `Portal 服务异常 · 第 2/5 次重试` |
| `network` 网络不可用 | 无 SSID / 无 DHCP / DNS 失败 / TCP 超时 | `FAILED` | ❌ | ✅ | ✅ | **`网络不可达`** | `未连接到校园网 · 网络失败 2/5` |
| `account_arrears` 欠费 | 服务端明确码 | `PAUSED`（立即） | — | — | ❌ | `账号已欠费` | `账号已停机，请联系网络中心` |
| `account_locked` 账号锁定 | 服务端明确码 | `PAUSED`（立即） | — | — | ❌ | `账号已被锁定` | `多次认证未通过，账号已锁定` |
| `retry_exhausted` 连续 5 次 | retryCount=5 或 netFailCount=5 | `PAUSED` | — | — | ❌ | `自动重连已暂停` | `连续失败 5 次，已停止自动重试` |

**两本账必须分开显示**（视觉 v1.1 提出的分账文案，体验侧接受并固化为规则）：计入 retryCount 的失败用 `· 第 N/5 次重试`；计入 netFailCount 的失败用 `· 网络失败 N/5`。用户能直接从文案看出"记的是哪本账"，从而判断该去改密码还是去插网线。

**`network` 的标题必须与另外两类不同**（`网络不可达` 而非 `认证失败`）。请求根本没发出去时写「认证失败」是错误归因，会把用户导向「去改密码」——最典型的误导型文案。只有 `credential` / `portal_service` 才叫认证失败。

**计数规则**：任一次成功（T2）双计数清零；`PAUSED → CONNECTING`（T9）也清零；切换学校（T12）清零。三类失败不得混算——否则「网线松了」会把账号锁死。

#### 1.5.1 `PAUSED` 三因（同状态、三种视觉，采纳视觉 v1.1 §6.3.3 并修正按钮文案）

| 原因 | 环 | 点 | 标题 | 主按钮 | 按钮宽度 |
|---|---|---|---|---|---|
| `retry_exhausted` | `--s-warn` 40% 弧 | 8px 琥珀**方块** r2 | `自动重连已暂停` | `恢复重连`，琥珀 tint 底（降权主要）h44 | 4 字 |
| `account_locked` | `--s-danger` 弧 | 8px 红**方块** r2 | `账号已被锁定` | `重新检测`，次要 h40 `--c-fill` 底 | 4 字 |
| `account_arrears` | `--s-danger` 弧 | 8px 红**方块** r2 | `账号已欠费` | `重新检测`，次要 h40 `--c-fill` 底 | 4 字 |

三条约束：

1. **接受红色弧**（视觉 v1.1 的判断）：欠费/锁定是"线路断了"而非"再试一下"，红色标记问题源头是对的。但**状态点必须保留 PAUSED 独有的方块形状**——形状是「暂停」的可辨识特征，只有色相变红；若点也换成圆形，`account_locked` 会与 `FAILED` 视觉混淆。
2. **按钮文案改用 `重新检测`（4 字），不用视觉 v1.1 的 `我已处理，重新检测`（7 字）**。理由：按钮文案在状态切换 **t=0** 即替换（见 §3.3），长度变化会造成横向跳动；`重新检测` 与 `重新连接` 同为 4 字，共用 `min-width 96px` 容器，零位移。语义上「重新检测」已隐含"我处理过了"，不需要第一人称。
3. **致命类按钮禁止 `--a-fill` / `--s-danger` 填充**（采纳视觉 v1.1 硬规则）。它不代表「再试一次」；红底按钮会诱导用户反复点击，而每一次点击都可能让锁定时长延长。
4. **副行按 18 全角重写（v1.2，原稿 27 全角违规）**：

| kind | 标题（已含事实） | 副行（只给原因 + 动作） | 字数 | 为什么这样写 |
|---|---|---|---|---|
| `account_locked` | `账号已被锁定` | `多次认证未通过，请联系网络中心` | 15 | 标题已说"锁定"，副行不再重复；补的是**原因**（为什么锁）与**动作**（找谁）。原因指向"多次认证未通过"而不是"你密码错了"，因为锁是重试策略触发的，不该让用户背锅 |
| `account_arrears` | `账号已欠费` | `请联系网络中心缴费` | 9 | 不写「请先充值」——本工具内没有缴费入口，给一个做不到的动作比不给更糟 |

两条都不含 `！`，都遵循「先事实、后动作」，且都不重复标题已有的信息（§0.4 原则 6）。

### 1.6 倒计时退避阶梯

> **v1.2.2 勘误**：原表第 5 行「45 秒后自动重试 → 到点进入 PAUSED」是**我自己写错的**。`MAX_FAIL = 5` 意味着**不存在第 6 次尝试**，那一行 45s 永远不可达；而且让用户对着一个"到点不会重试"的倒计时等 45 秒，比立刻告知"已暂停"更糟。现改为：**第 5 次失败 → 立即 `PAUSED`**，退避阶梯只覆盖前 4 次的间隔。

| 第 n 次尝试失败后 | 倒计时 | 倒计时条时长 | 文案 |
|---|---|---|---|
| 1 | 12s | 12000ms | `12 秒后自动重试` |
| 2 | 12s | 12000ms | `12 秒后自动重试` |
| 3 | 20s | 20000ms | `20 秒后自动重试` |
| 4 | 30s | 30000ms | `30 秒后自动重试` |
| 5 | — | — | **无倒计时**，立即进 `PAUSED`，副行 `连续失败 5 次，已停止自动重试` |

**规则**：条时长必须与文案秒数**严格一致**（条的 `scaleX` 线性映射剩余比例）；文案由剩余秒数驱动，模板 `{n} 秒后自动重试`，**不写死 12**。第 1 次为 12s 以满足产品既定文案；退避用于降低 Portal 侧被限流/锁号风险。用户手动「重新连接」（T7）不刷新阶梯序号，仍按当前 n 继续。

### 2.2 首屏绘制顺序（严格的层序，前端按此顺序插入 DOM）

1. canvas 底色（`--c-canvas`，同步内联，无闪烁）
2. 侧栏 / Tab Bar（玻璃外壳，无内容也先画，提供结构感）
3. 状态卡外框（尺寸固定，环占位）——**首屏最大元素必须先有位置**
4. 状态卡内容（标题/副行/按钮）
5. 数据块 → 开关卡 → 日志卡（stagger 入场）
6. 日志正文（最后，允许 100ms 后的异步填充）

> 规则：**任何 DOM 插入都不得改变已绘制元素的位置**。日志卡在无数据时也占位（`min-height` = 3 行 × 18px），不出现"日志来了页面往下窜"。

| # | 理由 |
|---|---|
| 1 | **语义错误**：横向滑动是"平级线性序列"的手势语言（日历、图库）。三个 Tab 是**并列功能集合**，不存在"下一页"。滑动会诱导用户继续横滑寻找第 4 页（不存在），产生"卡住"感。 |
| 2 | **手势冲突**：主页卡内已有分段控件与可横滚日志嵌块；横滑页面切换会与内部横向手势抢事件，出现"想滚日志却换了页"。 |
| 3 | **方向性代价**：横滑强制引入左右方向判断（Tab 序号差），需要为每种跨距定义不同位移与时长，直接违反「位移不超过 24px、单帧预算」的约束；且从 Tab 3 回 Tab 1 的 2×24px 位移在桌面窗口下会溢出内容区。 |
| 4 | **性能**：持续横滑期间两层毛玻璃（状态卡 + Tab Bar）同时在视口内移动，`backdrop-filter` 逐帧重算，中低端 GPU 掉到 40fps 以下。垂直 4px + 淡入只影响被切页自身。 |

### 3.2 Large Title 滚动折叠（移动）

| 属性 | 参数 |
|---|---|
| 折叠区间 | `scrollTop 0 → 32px`，**滚动驱动（scrub），无独立 duration** |

### 3.3 按钮（按压 / 释放 / 加载态）

| 项 | 参数 |
|---|---|
| 按下 | `transform: scale(0.97)`，`--d-xxs`/`--ease-press`；底色→`--a-fill-press`（主）/ `--c-fill-strong`（次），`--d-xxs` |
| 按下时延硬指标 | `pointerdown` → 进入 pressed **≤16ms（一个合成帧）**，**不等 IPC、不等状态机**。按压反馈与网络状态是两层（见 §1.2.1） |
| pending（异常路径） | 若 220ms 内仍未收到 `probe:start`（IPC 反常），保持「取消」文案 + `aria-busy`，**不二次改文案**；>5s 无任何事件 → `网络不可达`，Toast 报错且**不抢跑状态卡**（状态卡已先变） |
| 释放 | `scale(1)`，`--d-md`/`--ease-press`（释放比按下慢 2.2 倍，产生"弹性回位"） |
| 取消按压（指针移出） | `scale(1)`，`--d-xs`/`--ease-exit`，不做弹性 |
| 进入加载 | 文案 `opacity 1→0` `--d-xs`/`--ease-exit` → spinner `opacity 0→1` `--d-xs`（延迟 80ms）；**宽度锁定**：`min-width: 96px`，且实测当前宽度后写死 `width`（不做 width 过渡） |
| 加载中尺寸 | 主按钮 96×44(50) / 次按钮 96×40；文案区使用「同宽文本占位」策略：`正在连接` 与 `重新连接` 等长时复用宽度 |
| 防抖 | `pointerdown` 后 300ms 内忽略重复 `pointerdown`；提交后 **cooldown 600ms** 内按钮 `disabled`（视觉不置灰，仅不可点，避免闪烁） |
| 「取消」按钮可点时间 | `CONNECTING` 进入后 **400ms 后**才可点（防"还没开始就取消"） |
| hover（桌面） | 底色变化 `--d-sm`，**位移 ≤0（不位移）**；`--c-fill-strong` |
| 连续同长度文案切换（`重新连接` ↔ `取消`） | 同一按钮不换宽度：两态均锁定 `min-width 96px` |

### 3.5 状态卡（核心）

| 子项 | 参数 |
|---|---|
| **环形态切换**（如 270° 缺口 → 100% 满弧） | `stroke-dasharray`/`stroke-dashoffset` 从**当前值**向目标值插值，`--d-lg`/`--ease-state`；**只允许在状态切换时触发一次**，禁止循环修改 dasharray（非合成属性，每帧改会触发 SVG 重绘） |
| **环形态切换·旋转相位** | **保持当前旋转相位，绝不回到 12 点重画**。`CONNECTING → CONNECTED` 时，旋转在同一 320ms 内**从当前角速度减速到 0**（`--ease-state`），同时缺口补满——用户看到的是"转着转着补满了"，而不是"停住→重新画一遍"。回到 12 点重画会被读成"又重连了一次"（与视觉 v1.2 §6.3.1 同一约束） |
| **指示环旋转**（仅 `CONNECTING`） | `rotate 0→360deg`，**1200ms/圈**，`--ease-loop`（linear），`transform-origin: center`；通过 `animation` 而非 JS 逐帧；离开该态 `animation-play-state: paused` 后移除 |
| **状态点呼吸**（`CONNECTING`） | `opacity 1→0.4→1`，`2400ms` 循环，`--ease-state`，反向 alternate；**不动 scale**（视觉规范：仅按压族允许 scale） |
| **光晕呼吸**（`CONNECTED`，可选） | glow 独立图层 `opacity 0.55→0.85→0.55`，`2400ms` 循环；`scale` 禁止；不与环呼吸同相位（相位差 1200ms） |
| **状态色过渡** | 环 `stroke`、状态点 `fill`、glow `box-shadow`（或 glow 层 `background` + `opacity`）统一 `--d-lg`/`--ease-state`；**卡片背景、边框、阴影不参与过渡**（永远不变） |
| **标题 cross-fade** | 旧标题 `opacity 1→0` `--d-xs`/`--ease-exit`；新标题 `opacity 0→1` `--d-sm`/`--ease-enter`，延迟 80ms；两段共用 240ms 窗口（早于环完成 320ms 的 80ms，让文字先"落定"） |
| **按钮先换** | 按钮文案/形态在状态切换 **t=0** 即替换（`--d-xs`），**早于环**——防止用户在旧按钮上误触（视觉规范 §8.2） |
| **副行动画** | 同标题，但若只有数值变化（IP、次数），只做 `opacity 0.72→1` `--d-xs` 呼吸，不 cross-fade |
| **数字滚动（在线时长）** | 逐秒更新**不**滚动：字符直接替换（`tabular-nums` 保证宽度不变）+ `opacity 0.72→1` `--d-xxs`（"活着"的暗示）；**滚动动画仅用于跳变**（从 00:00:00 恢复、重连次数 +1）：每位 `translateY 0→-100%`（数字窗高 = 行高 44px）`--d-lg`/`--ease-state`，位间 stagger 30ms（最多 3 位） |
| **数字滚动容器** | 高度锁定（Display 行高 44px），`overflow: hidden`，每位独立 `span`，**任何时刻不改变容器尺寸** → 零重排 |
| **倒计时条**（`FAILED`） | `transform: scaleX(1→0)`，**12000ms**，`--ease-loop`（linear，占比必须线性）；`transform-origin: left`；条高 2px，`--s-warn`，`--r-xs` 端头 |
| **倒计时文案** | 每秒 `{n} 秒后自动重试`（`--s-warn-ink`，Footnote 13/400，mono）；数字由剩余秒数驱动，**文案不写死 12** |
| **倒计时被打断** | 条 `scaleX → 0` `--d-sm`/`--ease-exit`；文案 `opacity→0` `--d-xs`（同时置 `aria-live` 为 off） |
| **成功落定高光** | 状态卡内 `inset 0 1px 0` 高光 `0.72→1.0→0.72`，320ms，**仅成功一次**，不做循环脉冲 |
| 可打断 | ✅ 全部；新状态接管后旧动画立即移除，不排队 |

### 3.6 底部 Sheet（学校切换 / 主题选择）

| 项 | 参数 |
|---|---|
| 进入 | 背板 `translateY 100%→0` `--d-sheet`/`--ease-enter`；scrim `opacity 0→1` `--d-md`/`--ease-enter`；内容卡 `opacity 0→1` `--d-md`，延迟 80ms |
| 进入的"重量" | Sheet 是三层中最轻的一档（Toast < 按钮 < 卡片 < Sheet < 状态环），因此**不加 scale、不加弹性过冲**（过冲会与父级圆角错位） |
| 拖动跟随 | 1:1 直跟（`translateY = max(0, dy)`），**无惯性、无延迟**（延迟跟随在 60fps 下会产生"手感发飘"） |
| Rubber band | 向下超过 0 时：`damped = over * 0.35 / (1 + over / 240)`；系数 0.35，饱和分母 240px；上限 `damped ≤ 96px` |
| 只允许向下 | 向上拖动 `dy < 0` 时 `translateY` 恒为 0（不回弹、不露出，避免拖出窗口白边） |
| 松手判定（关闭） | **位移 ≥ sheet 高度 × 25%**（≤560px 窗口时为 ≥120px）**或** 向下速度 ≥ **0.8 px/ms**（取最近 100ms 加权平均）→ 关闭 |
| 松手判定（回弹） | 未达阈值 → `translateY → 0`，`--d-md`/`--ease-state`（不用 enter 曲线，ease-state 收尾更"稳"） |
| 关闭 | `translateY 0→100%` `--d-md`/`--ease-exit`；scrim `opacity→0` `--d-sm`；关闭后焦点回到触发元素 |
| 拖动起始区 | handle 区 24px + 内容区（**仅当内部 `scrollTop === 0` 时**）；顶部 44px 内的可点控件不参与拖动 |
| 防误触 | 垂直位移 **≥12px** 才进入拖动；`|dx| > |dy|` 时判为横向手势，不接管 |
| 可打断 | ✅ 仅进入可被打断（反向拖拽或 Esc 立即转退出曲线，从当前 translateY 起算） |
| 主题分段切换 | 指示块 `translateX` + `width` **不用 width 过渡**：改用固定槽内 `left/transform`（`--d-sm`/`--ease-state`）；主题色全局切换走 `--d-md` 交叉淡入（见 3.7 降级） |

### 3.7 切换学校的状态重置（T12，高风险）

| t | 事件 | 动效 |
|---|---|---|
| 0 | 用户点「切换 / 新增学校配置」 | Sheet 进入 340ms |
| — | 选择学校 → 若当前为 `CONNECTED` 或 `CONNECTING`：**必须二次确认** | 确认条（内联，不用新浮层）`opacity 0→1` `--d-sm` |
| 确认 | 断开会话 | 状态卡：内容 `opacity→0` `--d-xs`；环 `--s-idle` 320ms；**卡片外框不动**（关键：不塌缩、不转场白屏） |
| +120 | 重置计数与计时 | 数字滚回 00:00:00（滚动 320ms）；数据块 IP → `—`（cross-fade 120ms） |
| +160 | 落 `IDLE` | 「连接」主要按钮 `opacity 0→1` `--d-sm`；副行 `上次连接 —` |
| +320 | Toast | 「已切换到 {学校}」2.6s |

**注意**：切换学校**不自动连接**。理由：新学校凭据可能未完善，自动连接会把「配置错误」伪装成「认证失败」，让用户误判网络故障。

### 3.8 Toast / 行反馈 / 日志 / 分组入场

| 项 | 参数 |
|---|---|
| Toast 进入 | `translateY -12px→0` + `opacity 0→1`，**300ms**/`--ease-enter`；同时 `backdrop-filter` 从 0 到目标值由浏览器处理，不手动过渡 blur |
| Toast 停留 | 成功/信息 **2600ms**；错误 **4000ms**；带动作（撤销/重试）**5000ms**；鼠标悬停暂停计时（指针离开后补足剩余时间） |
| Toast 退出 | `translateY 0→-12px` + `opacity→0`，**180ms**/`--ease-exit` |
| 连续触发·同事件 | 500ms 内同一 `eventKey` → **替换内容并重置停留计时**，不叠加、不重播入场 |
| 连续触发·不同事件 | **队列，最多 1 可见 + 1 排队**；超过 2 条挤掉最旧；当前条退出 120ms 后下一条进入（总间隙 ≤420ms） |
| 位置 | 桌面：距顶 16，水平居内容区；移动：距顶 `safe-area-top + 16`；宽 `min(360px, 100% - 32px)`；**不遮挡状态卡环**（环顶距卡片顶 ≥20，Toast 高 ≤52 → 不重叠） |
| 列表行点击（我的/设置） | 底色→`--c-fill` `--d-xxs`；释放后 `--c-xs` 淡出；chevron `translateX 0→1px`（hover，`--d-sm`）；**行内不做整行 scale** |
| 日志新增行 | `translateY -6px→0` + `opacity 0→1`，`--d-md`/`--ease-enter`；已有行**不动**（用 `scrollTop` 补偿，不用整体 translate）；同时插入多行时 stagger 40ms（≤5 行） |
| 日志自动滚底 | `scrollTo` 平滑 **260ms**；用户手动上滚超过 24px 后暂停自动滚，出现「回到最新」pill（`opacity 0→1` `--d-sm`） |
| 分组入场 stagger | 卡片 `opacity 0→1` + `translateY 12→0`，`--d-md`/`--ease-enter`，stagger **40ms**，最多 5 项；总时长上限 **420ms**；**同会话内二次进入不重播**（记录 `hasEntered[route]`） |
| 空状态（日志为空） | 「暂无运行日志」`--t-2` 15/400 居中 + `doc-list` 40px 图标 `--t-4`；`opacity 0→1` `--d-md`，**无位移动画**（避免空状态"飘进来"） |

### 3.9 骨架 / 加载态

| 项 | 参数 |
|---|---|
| 适用范围 | **状态卡永不骨架化**（它是全页唯一视觉锚点，骨架会把它变成"空壳"，破坏首屏重量）。只有数据块、日志卡、完整日志页允许骨架 |
| 双阈值 | 数据加载 **>200ms** 显示**静态**骨架（`--c-fill` 实心块，无扫光）；**>600ms** 才启用 shimmer 扫光。≤200ms 直接出内容，杜绝"闪一下"；200–600ms 用静态块，避免"扫光刚开始就结束"的廉价感 |
| 骨架形态 | 与真实元素同尺寸同圆角（行高 52/56、数据格 64、日志行 18），颜色 `--c-fill`（12% 中性）；**几何必须与真内容逐像素对齐**，否则替换时会有一次不可见的重排 |
| shimmer | 高光带 `translateX(-100%→100%)`，**1400ms** 循环，`--ease-loop`；**禁动 `background-position`**（每帧重绘） |
| 骨架 → 内容 | 骨架 `opacity→0` `--d-xs` 与内容 `opacity 0→1` `--d-md` 同时进行（交叉 160ms），**只做 opacity，不做尺寸过渡** |
| 环加载（状态卡） | 读配置期间状态卡直出为 `IDLE`：静态灰轨道 + 标题 `未连接` + 副行 `正在读取配置…`；配置到达后走正常 T1/T13。**不显示 spinner**（避免与 `CONNECTING` 的旋转环混淆） |
| 全局禁用态 | 骨架期间不显示按钮的可点态（按钮以 40% 不透明占位，不 disable 视觉抖动） |

### 3.10 主题切换（浅/深）

| 项 | 参数 |
|---|---|
| 切换策略 | **不做整页交叉淡入**（两层全屏毛玻璃叠加会掉帧）；改为 CSS 变量在其默认过渡时间上统一 `--d-md`/`--ease-state` 过渡 `background-color` / `color` / `border-color` / `box-shadow` |

| 跟随系统 | 监听系统主题变化，切换动效同上；**不弹 Toast**（用户能看到结果） |
| 可打断 | ✅ 连续切换以最后一次为准 |

## 4. 手势与键盘规范

### 4.1 Sheet 下拉关闭（详参数，见 3.6）

| 参数 | 值 |
|---|---|
| 拖动启动阈值 | 垂直位移 ≥12px 且 `|dy| > |dx|` |
| 跟随比 | 1:1（`dy ≥ 0`） |
| Rubber band 系数 | 0.35，饱和分母 240px，下沉上限 96px |
| 关闭阈值·位移 | ≥ sheet 高度 × 25%（窗口高 ≤560 时 ≥120px） |
| 关闭阈值·速度 | ≥ 0.8 px/ms（最近 100ms 加权） |
| 回弹 | `--d-md` / `--ease-state` |
| 关闭 | `--d-md` / `--ease-exit` |
| 禁止 | 向上拖出屏幕顶部；拖动中触发内部滚动；scrim 上做水平滑动关闭 |

### 4.2 主页下拉刷新（仅触屏/触控板，鼠标滚轮不触发）

| 参数 | 值 |
|---|---|
| 触发距离 | **72px** |
| 阻尼 | `offset = overscroll × 0.55`（`overscroll > 0` 时） |
| 视觉反馈 | 环上方 16px 出现刷新指示器；`0–72px` 映射为环轨道的进度弧（`stroke-dashoffset` 0→25%），**不出现第二次旋转环** |
| 释放达阈值 | 进入刷新态：指示器旋转 1200ms/圈；最小展示 **600ms**（防"一闪而过"）；随后回弹 `--d-md` |
| 释放未达阈值 | 回弹 `--d-lg`/`--ease-state`（比关闭慢，让用户看到"取消"） |
| 刷新动作语义 | 立即执行一次 T10 逻辑（心跳 + 重连判定），不改变状态机状态名，只在日志追加 |
| 禁止 | `CONNECTING` 期间触发刷新（下拉只显示阻尼位移，释放即回弹，不动作） |

### 4.3 滚动与边缘

| 项 | 规范 |
|---|---|
| 边缘回弹 | 桌面不启用（Windows 无惯例）；移动触屏 `overscroll-behavior-y: contain`，不传递到窗口 |
| 顶部渐隐遮罩 | `--c-canvas-deep` 高 24px，`scrollTop > 8px` 时 `opacity 0→1` `--d-sm`；到底部对称处理 16px |
| 滚动条 | 覆盖式 4px 宽，`--c-sep-strong`，hover 才加宽至 8px（`--d-sm`）；不占布局宽度 |

## 5. 反馈三级策略

### 5.1 分工（同一区域同时只允许一级）

| 级别 | 载体 | 谁用 | 时长 | 何时用 | 禁止 |
|---|---|---|---|---|---|
| **L1 内联** | 按钮内 spinner + 文案替换 | 用户主动触发的操作 | 操作期间 | 用户刚点了按钮、需要知道"点到了且在跑" | 禁止同时弹 Toast 说"正在连接" |
| **L2 卡内** | 状态卡副行 + 2px 倒计时条 | 状态机自发的状态变化 | 持续到状态变化 | 认证失败/自动重试/暂停 | 禁止用 Toast 播报失败（会被状态卡覆盖重复） |
| **L3 全局 Toast** | 顶部玻璃条 | **页面内无处安放**的事件 | 2.6/4/5s | 切换学校成功、复制成功、配置已保存、日志目录已打开、托盘恢复 | 禁止用于状态变化、表单校验错误、连接结果 |

**同时出现的硬规则**
1. 状态卡的**任何状态变化都不弹 Toast**——状态卡本身就是反馈载体。
2. L1 与 L2 可在同一屏共存（按钮 spinner + 卡内倒计时可同时？→ **不允许**：`FAILED` 时按钮无 spinner，`CONNECTING` 时无倒计时，物理上互斥）。
3. L3 出现时若与 L1 时间重叠，Toast 延迟 120ms 进入（等按钮态先落定）。
4. 同一时刻 **最多 1 条 Toast**（+1 排队）。
5. 全屏只有 **1 处 `aria-live` 播报源**（状态卡标题），Toast 使用独立 `role="status"`，但失败类改为同一 live region 以避免双播报。

**「环点标红、副行不标红」的不对称规则（v1.2，必须守住）**：`network` 失败时，**环与状态点用 `--s-danger`**（机器视角的事实：线路确实异常，用户要一眼看到），但**副行墨色固定 `--t-2`，不得用 `--s-danger-ink`**（对用户的说法：网线松了不是你的错，红色文案会让人以为被指责）。

### 7.1 reduced-motion 降级（`prefers-reduced-motion: reduce`）

### 7.4 ARIA 要点

| 元素 | 标注 |
|---|---|
| 状态卡标题 | 唯一 live region：`role="status" aria-live="polite" aria-atomic="true"`，内容为「标题 + 副行」合并字符串；`FAILED`/`PAUSED` 切换时临时改 `assertive`（200ms 后复位，避免后续秒级更新抢占） |
| 副行（含秒级倒计时） | `aria-live="off"`；倒计时用 `aria-label` 提供一次完整语义（``12 秒后自动重试``），**每秒不重播**（否则读屏用户无法使用） |
| 进度环 SVG | `aria-hidden="true"` + `focusable="false"`；信息由标题/副行承担 |
| 倒计时条 | `role="progressbar" aria-valuemin=0 aria-valuemax=12 aria-valuenow={剩余} aria-valuetext="{n} 秒后自动重试"`；`aria-live="off"` |
| 主按钮 | 原生 `<button>`；加载态 `aria-busy="true"` + `aria-label="正在连接"`，且**保持可聚焦**（disabled 会丢焦点） |
| 开关 | `role="switch" aria-checked` + `aria-labelledby`（行标签）+ `aria-describedby`（副行说明） |
| 分段控件（主题） | `role="radiogroup"` + 每项 `role="radio" aria-checked`；roving tabindex |
| 侧栏 / Tab Bar | `<nav>` + `aria-current="page"`；Tab Bar 用 `role="tablist"` + `role="tab"` + `aria-selected` |
| Sheet | `role="dialog" aria-modal="true" aria-labelledby="sheet-title"`；打开时 focus trap，关闭后 restore focus；**背景层（侧栏 / Tab Bar / 内容区）同时置 `inert`**（不可交互 + 不可聚焦 + 读屏跳过），与 `.glass-frozen` 在一次状态更新里同时生效，省一次重排 |
| 日志列表 | `role="log"` + **`aria-live="off"`**（见下方勘误） |
| 图标 | 纯装饰 `aria-hidden="true"`；有语义的图标按钮必须有 `aria-label`（如 `aria-label="刷新状态"`） |
| 空值 | `—` 需 `aria-label="无数据"`，避免读屏念"破折号" |

#### v1.2.2 勘误：日志改为静默，播报只由状态卡承担

原表写「日志 `aria-live="polite"` + `aria-relevant="additions"`」，与本节的「**live region 全站唯一**」**互相矛盾**——两者不能同时成立。取唯一性，理由：

1. 认证过程中日志每秒可能新增 1 条，`polite` 会持续排队播报，读屏用户**永远听不到自己触发的那句反馈**；队列还会挤掉状态卡的关键播报（最坏情况：用户不知道已经连上了）。
2. 日志是**可回看的次要信息**（有专门的全量日志页），而状态是**必须即时知道的**。主次分明时，让次要信息静默是正确的取舍。
3. 用户仍可主动读：`role="log"` + `tabindex="0"` + `aria-label="最近运行日志"` 保留，键盘聚焦后可按行朗读。

**结论**：日志容器 `role="log" aria-live="off"`，滚动与焦点能力保留；**全站唯一 live region 就是状态卡 `#live`**。若将来要做「播报日志」开关，需作为独立偏好项，默认关。

### 7.5 焦点与动效的配合

- 状态变化后**不主动移动焦点**（会打断读屏）；只更新 live region。
- Sheet 关闭、Toast 消失后焦点回到触发元素；Toast 本身不可聚焦（除非带动作按钮）。
- `prefers-contrast: more` 时：玻璃层改不透明底（复用视觉规范 §4 降级配方），所有 hairline 提升到 `--c-sep-strong`，焦点环加粗到 3px `--a-text`。
- 缩放 200% 时：内容区 `max-width: 760px` 变为单列、状态卡环降级到 96px（不低于），不出现横向滚动。

## 8. 性能约束

### 8.1 只允许走合成的属性

| 允许 | 禁止 |
|---|---|
| `transform`（translate / rotate / scale 仅按压）、`opacity` | `width` `height` `top` `left` `margin` `padding` `font-size` `stroke-dasharray`（循环时） |
| `background-color` / `color` / `border-color` / `box-shadow`（**有限度**：只在离散状态切换时一次性过渡，不在循环动画里动 box-shadow） | 循环动画中使用 `box-shadow` / `filter: blur()` / `background-position` |
| `stroke-dashoffset`（仅一次性状态切换） | JS 逐帧改样式（除 rAF 驱动的旋转守卫） |

**光晕实现约束**：`CONNECTED` 呼吸的 glow 用独立绝对定位图层（`radial-gradient` + `opacity` 动画），**不要**对状态卡本身做 `box-shadow` 动画（会触发卡片整块重绘，且毛玻璃层重算）。

### 8.2 必检的布局抖动点

| 风险点 | 措施 |
|---|---|
| 5 状态切换导致卡片高度变化 | 卡片 `min-height` 268/300 + 内容 `position` 固定；按钮高度按状态在 44/40 间变化 → 用**等高容器 + 内部居中**（容器 50px，按钮 40 时上下各 5px 留白），不改变外框 |
| 倒计时条出现/消失挤压内容 | 条绝对定位于卡片底部（`bottom: 0`，`padding-bottom: 20` 恒留空间），**不参与文档流** |
| 在线时长逐秒更新导致宽度变化 | `font-variant-numeric: tabular-nums` + 数字窗固定宽；mono 字族 |
| 日志行插入导致页面跳动 | 日志卡位置固定 + `padding-bottom: 20`；**桌面固定 5 行 = 90px、移动固定 3 行 = 54px**（用 `max-height` 锁定，不用 `min-height` 撑开），无数据时也保持该高度不塌缩 |
| 标题从 `正在连接…`（省略号逐点）变长 | 省略号用固定宽度三槽容器逐点显隐，**不改变文本长度**；标题容器 `min-height: 28px` |
| 副行文案长度差异（IP 长短） | 副行 `white-space: nowrap`，高度锁定 18；**不用 `text-overflow: ellipsis` 兜底**（被截断的失败原因等于没写）。**纯中文 ≤18 全角；含 ASCII 的混合串按实测 ≤288px**（§1.4）；动态拼接超限按优先级丢动态部分 |
| 按钮文案切换导致宽度跳动 | `min-width: 96px` + 加载态实测锁宽（见 3.3）；文案长度限 2/4 字档（见 §6.2） |
| 阶段推进导致按钮位移 | CONNECTING 的副行容器 `min-height: 18px` 单行替换，**禁止打字机/纵向滚动**；若采用阶段指示器必须 `position: absolute`（见 §1.4.1，建议不采用） |
| Toast 出现推挤内容 | `position: fixed`，不参与布局 |
| 骨架 → 内容替换 | 同尺寸占位，交叉淡入，无尺寸过渡 |
| Large Title 折叠 | 顶栏高恒定 44，不生长（见 3.2） |

### 8.3 单帧预算（60fps = 16.7ms）

| 阶段 | 预算 | 说明 |
|---|---|---|
| Style + Layout | **≤3ms** | 靠"零布局动画"保障；日志用 `contain: layout paint` |
| Paint | **≤5ms** | 毛玻璃最多 2 面同时重绘；避免大面积 `box-shadow` 动画 |
| Composite | **≤5ms** | 动画元素各自独立层（不超过 6 个合成层）；`will-change` 仅动画期间 |
| 余量 | **≥3.7ms** | 留作 GC / IPC 回调 |
| 长任务 | **≤8ms** | 日志批量写入合并（100ms 窗口），配置解析放 `requestIdleCallback` |
| 首次可交互 | **≤400ms** | 骨架直出；配置读取同步但目标 ≤50ms |
| 状态切换整体 | **≤320ms** | 用户感知"一条动效"而非"两段" |

**降级守卫**：连续 3 帧 >24ms 时，自动关闭光晕呼吸与非关键 stagger（一次性降级，不恢复，写入日志）。此守卫与 reduced-motion 独立。

### 8.4 长列表与日志上限

| 项 | 上限 | 策略 |
|---|---|---|
| 主页日志 DOM | **200 行** | 超出移除最早节点（`removeChild`，不用 `innerHTML` 重建） |
| 主页日志可视 | 桌面 **5 行 = 90px** / 移动 **3 行 = 54px** | `max-height` 锁定，`overflow: hidden`；桌面允许卡内滚动，**移动端禁卡内滚动**（嵌套滚动在触屏上是陷阱，只显示最近 3 行 + 底部「查看完整日志」） |
| 日志列布局 | 时间戳列固定 **56px** 右对齐 `--t-3`，正文 `--t-1` | **不用 1px 竖线分隔**（12px 行高里会显脏）；行间不加圆角 |
| 完整日志页 | 虚拟列表 | 行高固定 18px + `padding: 8px 0`（实际步长 34），窗口 40 行 + 上下 10 行缓冲；DOM ≤60 行；hover 整行 `--c-fill` |
| 日志写入节流 | 100ms 合并 | 同窗口内多条合并为一次插入 |
| 日志滚动跟随 | 用户距底 ≤24px 才自动跟随 | 否则显示「回到最新」pill |
| Toast 队列 | 1 可见 + 1 排队 | 见 3.8 |
| 动画并发 | **≤2** | 视觉规范 §8.2；状态切换时环 + 文案算 1 组 |
| 合成层 | ≤6 | 状态卡、环、glow 层、Toast、Sheet、日志滚动容器 |
| 后台化 | 窗口隐藏/托盘 → 所有 `animation-play-state: paused`；心跳继续（纯计时器，不渲染） | `visibilitychange` + 主进程窗口事件 |
| 毛玻璃 | 屏幕内 ≤2 面同时可见（侧栏/Tab Bar 二选一 + 状态卡；Toast 出现时临时 3 面，需 ≤400ms） | 极端低端设备可把状态卡降为实心（保留 r20 + L3 阴影） |

### 8.5 层叠标尺与「玻璃不得压在遮罩下」

采纳视觉 v1.1 §9.4 的 z-index 标尺，并补一条**必须写进实现的硬约束**：

| z | 层 | 备注 |
|---|---|---|
| 0 | 背景 | `--c-canvas` |
| 1 | 内容 | 卡片流 |
| 10 | 侧栏 · Tab Bar | 玻璃 |
| 20 | 吸顶（顶栏 / toolbar） | 玻璃（移动折叠态） |
| 30 | 遮罩 scrim | 浅 `rgba(16,16,20,.28)` / 深 `rgba(0,0,0,.52)` |
| 40 | Sheet | `--r-xl 20`，上圆下直，宽 `min(560px, 100%)` |
| 50 | Toast | 玻璃 |
| 60 | 模态（确认/引导） | — |

**硬约束**：**玻璃元素绝不能与 z ≥ 30 的遮罩重叠**。原因：遮罩层会吃掉 `backdrop-filter` 的采样源，玻璃瞬间变实心——这不是渐变而是**突变**，用户会看到"浮层出现的一瞬间侧栏跳了一下"。

具体影响两处，必须处理：
1. **Sheet 打开时**：侧栏（z10）与 Tab Bar（z10）在 scrim（z30）下方 → 它们会从玻璃变实心。对策：Sheet 打开时给侧栏/Tab Bar 加 `.glass-frozen`，**主动降到不透明底**（视觉规范 §4 降级配方），与遮罩同时以 `--d-md` 过渡，把突变变成渐变。
2. **Toast（z50）高于 scrim（z40）**：Toast 在 Sheet 之上仍若要保留玻璃，它的采样源是 scrim（半透明黑），blur 结果接近纯色 → 视觉上等于实心，还白付一次合成。对策（v1.2 定稿）：**`z > 30` 的浮层一律不用 `backdrop-filter`**，Toast 在遮罩上改用**纯不透明底**——浅 `#FFFFFF` / 深 `#1C1C22`，保留 `--c-glass-border` 描边与 L3 阴影。纯色比 0.94 半透明更干净（0.94 仍会透出一点点遮罩下的内容，那点透出正好让人怀疑"是不是没遮住"）。

**体验侧补充**：Toast z50 高于 Sheet z40 是必要的（用户在 Sheet 内切换学校要看到确认反馈），但要求 Toast 在 Sheet 场景下**水平居中于 Sheet 而非窗口**，否则视觉上会"浮在遮罩外面"，让人误以为 Sheet 已经关闭。

**附：背景 `inert`（v1.2）**。Sheet 打开时侧栏 / Tab Bar / 内容区必须置 `inert`——它同时解决三件事：键盘 Tab 不逃出浮层、读屏不念背后的内容、点击不穿透。`.glass-frozen`（视觉降级）与 `inert`（语义隔离）**必须在同一次状态更新里同时生效**，否则会出现"背景已冻结但仍可点"或"背景已冻结但读屏还在念"的错位。

| R1 | **切换学校会断开当前会话** | 用户在教学楼断网，误切换后 10 分钟内连不上 | 仅当 `CONNECTED`/`CONNECTING` 时弹内联二次确认（文案 `切换学校会断开当前连接，需要重新认证`）；确认按钮非 destructive 红，用 `--a-fill`；「取消」默认焦点 | 若用户 30s 内未确认，自动取消；切回原学校配置 1 键可达（学校 Sheet 顶部「当前学校」置顶 + 撤销 Toast 5000ms） |

| R9 | **读屏用户遇秒级更新** | 每秒播报，无法操作 | 倒计时 `aria-live="off"` + 单一 live region 只播报状态标题 | 提供「播报倒计时」开关（默认关） |
| R10 | **低端 GPU 毛玻璃掉帧** | 滚动卡顿 | 毛玻璃 ≤2 面；骨架期不启用 blur；帧率守卫自动降级 | 状态卡可通过设置项降为实心（`不透明底 + L3 阴影`），功能无差异 |
